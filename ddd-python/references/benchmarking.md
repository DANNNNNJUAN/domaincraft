# 评估 Skill 的改造效果

简体中文 · [English](benchmarking.en.md)

工具自测回答“检查器是否按规则工作”。要回答“Skill 是否改善了重构结果”，需要独立任务、独立验收和可比较的实验条件。

## 比较条件

固定起始代码、任务、模型、预算和验收版本，再比较三种条件：不提供 Skill、只提供设计指导、提供完整 Skill。每次使用干净上下文，避免前一条件的指导影响后一条件。先固定候选提交，再运行验收；反复看着验收修答案的结果应归为开发校准。

重复运行并保留失败、超时和缺失提交。分别记录旧行为回归、新规则、可替换实现契约、依赖边界和语义评审，逐项报告 PASS/FAIL。类、模式和注释的数量不合成为设计分数。

## 区分结果来源

外部 benchmark 的 prepare/run/compare 工具可以验收保存的代码，它们属于实验设施。测试执行无需大模型 API，生成候选代码则是独立阶段。已知测试的参考实现用于校准时，要在报告中标明。

开发题用于完善工具，未见过的保留题用于评估泛化。已经看过的题目或参考答案不再属于盲测集。模型或预算记录不完整时，报告代码之间的观察差异即可。

注释准确性、领域边界和模式成本仍需语义评审。把这些判断与可执行结果一起保存，便于后来复查。
